## Що робити

Рев'ю змін у поточній гілці відносно `main` (`git diff main...HEAD`).

**Не змінювати код**, якщо про це не попросили окремо. Результат — список зауважень.

## Чек-лист

1. **Коректність щодо Syrve** — поля й поведінка відповідають `docs/syrve-api-notes.md`:
   - баланс береться за `SYRVE_WALLET_ID`, а не першим гаманцем;
   - перед `chargeoff` перевіряється баланс (Syrve пускає в мінус);
   - «гостя не знайдено» = HTTP 400 з `Validation_IncorrectPhone`, інші 400 не ковтаються;
   - транзакції для сповіщень фільтруються: наш `walletId` і `sum !== 0`;
   - `revision` не втрачає точність (BigInt / string).
2. **Секрети** — `apiLogin`, токени, паролі не потрапляють у код, логи, тести, `docs/`, повідомлення комітів.
3. **Помилки** — помилки Syrve й Telegram обробляються; користувач бачить зрозумілий текст українською; у логах є `correlationId`.
4. **Ідемпотентність** — повторний запит / подвійний клік / ретрай не нараховує й не списує двічі; одне повідомлення на одну транзакцію.
5. **Архітектура** — HTTP до Syrve лише через `SyrveClient`; контролери й хендлери бота тонкі; баланс не зберігається в нашій БД.
6. **Міграції** — зміни схеми лише через нову міграцію Prisma; застосовані міграції не редагуються.
7. **Тести** — для критичної логіки зі списку в `CLAUDE.md` є unit-тести; `npm test` проходить.
8. **Зайве** — нові бібліотеки, шари чи функції поза задачею етапу.
