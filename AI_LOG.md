## Як працював

1. ТЗ → план і правила для агента (`PLAN.md`, `CLAUDE.md`) до першого рядка коду.
2. Розвідка Syrve API в Postman: кожне припущення ШІ про API перевірив на живих даних і записав у `docs/syrve-api-notes.md`. Агент читає цей файл, а не вгадує поля.
3. Кожен етап — окрема гілка: запит → план від Claude Code → моє «ок» → реалізація з unit-тестами на критичну логіку → ручна перевірка → рев'ю Codex → PR → merge у `main`.
4. Перехресна перевірка: код пише Claude Code, перевіряє Codex — інша модель частіше помічає те, що автор пропустив.

## Що вирішив сам, а не ШІ

- Програма лояльності: з трьох бонусних обрав «в зале и в доставке» (найновіша, увімкнені сповіщення), `programId` і `walletId` задаються в `.env`.
- Не робити Telegram Mini App: потребує публічного HTTPS, а для трьох дій (картка, баланс, історія) текстовий бот достатній.
- Каркас підготував напередодні, щоб день пішов на логіку; уся бізнес-логіка — 09.11.
- Імʼя питаємо лише в нового гостя: існуючому в Syrve не перезаписуємо імʼя і не додаємо зайвий крок (відмінність від ТЗ — у звіті).
- QR генеруємо локально (`qrcode`), а не через зовнішній сервіс — номер картки не йде третій стороні.
- Якщо в гостя немає гаманця нашої програми — не тихий 0, а попередження в лозі; у боті — 0.
