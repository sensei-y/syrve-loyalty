## Як працював

1. ТЗ → план і правила для агента (`PLAN.md`, `CLAUDE.md`) до першого рядка коду.
2. Розвідка Syrve API в Postman: кожне припущення ШІ про API перевірив на живих даних і записав у `docs/syrve-api-notes.md`.
   Агент читає цей файл, а не вгадує поля; чого там немає — перевіряє на живому API до коду.
3. Кожен етап — окрема гілка: запит → план від Claude Code → моє «ок» → реалізація з unit-тестами на критичну логіку →
   ручна перевірка на живому API і в Telegram → рев'ю Codex → виправлення → merge у `main` **без PR**, fast-forward.
4. Перехресна перевірка: код пише Claude Code, перевіряє Codex — інша модель частіше помічає те, що автор пропустив.
   За день Codex дав понад 20 зауважень; більшість — про ідемпотентність і дублі.

| 4 | Claude: текст помилки Syrve переносився в `SyrveApiError.message` | `access_token` з невірним ключем повертає сам `apiLogin` у тексті — ключ міг потрапити в лог | Агент перевірив запит із фейковим логіном на живому API; тест відтворив відповідь і впав → текст помилки токена відкидається |

| 6 | Claude: `PENDING` записується до виклику Syrve і завершується після | Якщо api впаде посередині, запис назавжди лишиться `PENDING` | Рев'ю Codex; при старті api незавершені → `UNKNOWN`, звірка в кабінеті, без автоповтору |
| 7 | Claude: id гостя з URL як ключ черги операцій, без нормалізації | Syrve приймає id у будь-якому регістрі → `ABC…` і `abc…` у різних чергах, два списання проходять перевірку балансу | Рев'ю Codex; id → нижній регістр. ### Інші, дрібніші

- Назви полів Syrve за аналогією з iiko — у `/program` ключ `Programs` з великої літери (Postman).
- «Гостя не знайдено» — не 404, а HTTP 400 зі своїм `errorCode` для кожного типу пошуку; агент перевірив коди для картки й id на живому API до коду.
- «Бракує OpenSSL для Prisma на Alpine» — насправді дубльовані порожні рядки в `.env`; валідація конфігу назвала змінні.
- Інтерфейс `SyrveClient.createCustomer()` з готовою карткою — у Syrve це 3 окремі виклики (рев'ю Codex, переписано в О2).
- `prisma migrate dev` на `localhost:5432` — там локальний PostgreSQL Windows; міграції генеруються через `prisma migrate diff`.
- Ручна перевірка через `curl` у Git Bash — кирилиця пішла не в UTF-8, у журнал і в Syrve потрапили «������»; не-ASCII тепер перевіряю з Node.
- Після `UNKNOWN` форма видавала новий ключ — повторний клік міг задвоїти нарахування; форма блокується до звірки (Codex).
- Лічильник невдалих входів ріс без меж через підроблений `X-Real-IP` — рахуємо лише існуючі логіни (Codex, після мого ж виправлення).
- Після зміни `ADMIN_LOGIN` старий адмін входив зі старим паролем — входить лише поточний (Codex).
- Розклад поллера живе в Redis і зник би після `FLUSHALL` — worker відновлює його раз на хвилину (агент сам, готуючи перевірку).
- `revision` через `Number()` втрачав точність після 2^53, базова точка обрізалась на 200 сторінках — `context.source` / `JSON.rawJSON`, база до кінця історії (Codex).

## Що вирішив сам, а не ШІ

- Програма лояльності: з трьох бонусних обрав «в зале и в доставке» (найновіша, увімкнені сповіщення), `programId` і `walletId` задаються в `.env`.
- Каркас підготував напередодні, основну бізнес-логіку зробив 09.11; 10.11 при фінальній звірці з ТЗ виправив mock для наскрізного показу без Syrve.
- Імʼя питаємо лише в нового гостя: існуючому в Syrve не перезаписуємо імʼя і не додаємо зайвий крок (відмінність від ТЗ — у звіті).
- QR генеруємо локально (`qrcode`), а не через зовнішній сервіс — номер картки не йде третій стороні.
- Немає гаманця нашої програми — «Баланс недоступний», а не тихий 0.
- Пошук у панелі — по всіх гостях Syrve, а не лише по зареєстрованих у боті.
- Додаткова функція — Д1 (історія): транзакції вже читаються для О6, той самий фільтр. Не робити Telegram Mini App: потрібен публічний HTTPS, для картки, балансу й історії текстового бота досить.
- Merge у `main` без PR, fast-forward; рев'ю Codex — до merge.
