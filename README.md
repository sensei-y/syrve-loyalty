# Syrve Loyalty

Сервіс лояльності поверх Syrve Cloud API. Гість реєструється в Telegram-боті, отримує картку з QR і бачить баланс та історію.
Адміністратор у веб-панелі знаходить гостя за телефоном, нараховує й списує бонуси з причиною і бачить журнал.
Про будь-яку зміну балансу гість отримує повідомлення в Telegram — і з панелі, і з кабінету Syrve.

Документи: [ARCHITECTURE.md](./ARCHITECTURE.md) — як влаштовано, [REPORT.md](./REPORT.md) — звіт,
[AI_LOG.md](./AI_LOG.md) — робота з ШІ, [docs/syrve-api-notes.md](./docs/syrve-api-notes.md) — перевірена поведінка Syrve API.

## Вимоги

- Docker і Docker Compose.
- Для запуску без Docker і тестів — Node.js 22+.
- Для режиму `real`: доступ до Syrve Cloud API (`apiLogin`) і бот від [@BotFather](https://t.me/BotFather).

## Запуск

```bash
cp .env.example .env
```

Заповніть у `.env`:

| Змінна | Що це | Де взяти |
|---|---|---|
| `ADMIN_PASSWORD` | пароль адміна панелі (мін. 8 символів); логін — `ADMIN_LOGIN`, за замовчуванням `admin` | придумати |
| `JWT_SECRET` | підпис сесії панелі (мін. 32 символи) | `openssl rand -hex 32` |
| `TELEGRAM_BOT_TOKEN` | токен бота; порожньо — бот і сповіщення вимкнені, решта працює | @BotFather → `/newbot` |
| `SYRVE_MODE` | `real` — живий Syrve, `mock` — без Syrve (див. нижче) | — |
| `SYRVE_API_LOGIN` | ключ API Syrve | кабінет Syrve → API-логіни |
| `SYRVE_ORGANIZATION_ID` | організація | `POST /api/1/organizations` |
| `SYRVE_PROGRAM_ID` | програма лояльності — в організації їх кілька, задається явно | `POST /api/1/loyalty/syrve/program` → `Programs[].id` |
| `SYRVE_WALLET_ID` | гаманець цієї програми (≠ `programId`) | там само → `Programs[].walletId` |

Решта змінних має робочі значення за замовчуванням — пояснення в [.env.example](./.env.example).
Якщо `programId` і `walletId` не збігаються з даними Syrve, `/api/health/syrve` скаже про це в лозі api.

```bash
docker compose up --build
```

Спершу одноразовий сервіс `migrate` застосовує міграції, потім стартують `api` і `worker`.

| Що | Адреса |
|---|---|
| Адмін-панель (вхід — `ADMIN_LOGIN` / `ADMIN_PASSWORD`) | http://localhost:8080 |
| Стан API, Postgres, Redis | http://localhost:8080/api/health |
| Звʼязок із Syrve: організація й програма | http://localhost:8080/api/health/syrve |

`COOKIE_SECURE=false` у `.env.example` — для локального `http://localhost:8080`. За HTTPS приберіть рядок або задайте
`true`: cookie сесії отримає прапорець `Secure`. Входить лише поточний `ADMIN_LOGIN`; зміна лише `ADMIN_PASSWORD` не скасовує
вже видані сесії (до 12 год) — щоб скинути всі, змініть `JWT_SECRET`.

### Mock-режим

`SYRVE_MODE=mock` (за замовчуванням) — сервіс піднімається без доступу до Syrve: гості, картки, баланс і транзакції — в памʼяті.
**Обмеження:** памʼять у кожного процесу своя. Гість, зареєстрований у боті (`worker`), не видний у панелі (`api`), і навпаки;
після рестарту дані mock зникають. Mock — щоб перевірити запуск, бота або панель окремо, але не наскрізний сценарій.

## Як перевірити О1–О6 і Д1

Режим `real`, заповнений `.env`, `docker compose up --build`.

**О1 — підключення до Syrve.** Відкрийте http://localhost:8080/api/health/syrve → `status: ok`, назва організації й програми.
Помилка (наприклад, невірний `SYRVE_WALLET_ID`) → 503 «Немає зв'язку з Syrve», причина — у `docker compose logs api`.

**О2 — реєстрація в Telegram.**
1. У боті `/start` → «📱 Надіслати контакт» (приймається лише власний контакт, номер — український `+380`).
2. Якщо гостя з таким телефоном у Syrve ще немає, бот питає імʼя. Якщо є — імʼя не питає й не перезаписує.
3. Бот відповідає «Готово…» і надсилає картку. У кабінеті Syrve гість зʼявиться в програмі з 10-значною карткою.
4. Повторна реєстрація (`/start` ще раз або той самий номер з іншого Telegram) — той самий гість, без нової картки.

**О3 — картка й баланс.** «💳 Моя картка» → QR із номером картки, номер і баланс гаманця нашої програми
(«Баланс: 4 бонуси»). Немає гаманця програми — «Баланс недоступний», а не 0.

**О4 — вхід і пошук.**
1. Без входу http://localhost:8080 показує лише форму входу, а `/api/*` (крім `/api/auth/login` і `/api/health*`) → 401.
2. Увійдіть, знайдіть гостя за телефоном у будь-якому форматі (`0991234567`, `+380 99 …`): імʼя, телефон, картка, баланс,
   чи привʼязаний до бота. Пошук іде по всіх гостях організації в Syrve, не лише по зареєстрованих у боті.
3. Багато невдалих входів поспіль → 429 «Забагато невдалих спроб».

**О5 — нарахування / списання.**
1. У картці гостя: «Нарахувати», сума, причина (3–200 символів) → «Виконано», баланс оновився.
2. «Списати» більше, ніж є на рахунку → «Відхилено: Недостатньо бонусів» (Syrve пускає в мінус — перевіряємо самі).
3. «Журнал операцій панелі»: коли, хто, тип, сума, причина, статус.
4. Подвійний клік не створює дві операції. Якщо Syrve не відповів, статус «Невідомо — перевірте в кабінеті Syrve»,
   форма блокується до звірки.

**О6 — сповіщення.** Протягом ~30 с після зміни балансу гість отримує «Нараховано N бонусів. Баланс: M» /
«Списано N бонусів. Баланс: M»:
- з панелі — нарахуйте або спишіть, як в О5;
- з кабінету Syrve — Гості → Chain/Store «Демо В.С.» → **Update** (список не вантажиться сам) → відкрити гостя →
  вкладка **Balance** → у гаманця програми **Top up** / **Write off** з коментарем.

Одна операція — одне повідомлення; рестарт `worker` не надсилає повторів; історія до реєстрації не надсилається.

**Д1 — історія операцій.** У боті «📜 Історія» → останні 10 змін балансу з часом і балансом після.
У панелі в картці гостя «Історія в Syrve» — останні 20 з коментарем (панель, каса, кабінет).

## Тести

```bash
cd api
npm install
npx prisma generate
npm test
```

Unit-тести (Jest) на критичну логіку: токен і помилки Syrve, нормалізація телефону, реєстрація без дублів, вибір гаманця,
списання понад баланс, ідемпотентність операцій, фільтр і дедуп сповіщень, outbox, історія. Мережі не потребують:
Syrve підміняється mock-клієнтом або підміною `fetch`.

## Локальний запуск без Docker

Перевірено лише запуск у Docker; цей розділ — для розробки.

```bash
docker compose up -d postgres redis
cd api && npm install
set -a && . ../.env && set +a   # код і Prisma читають змінні оточення, .env з кореня самі не підхоплюють
npx prisma migrate deploy
npm run dev:api      # API
npm run dev:worker   # в іншому терміналі (з тими самими змінними)
cd ../admin && npm install && npm run dev
```

`DATABASE_URL` і `REDIS_HOST` для цього режиму вже є в `.env.example` (`localhost`).
Якщо на машині встановлено локальний PostgreSQL, він може займати `127.0.0.1:5432` — тоді `localhost:5432` веде не в базу
з Docker. Зупиніть локальний PostgreSQL або змініть порт у `docker-compose.yml` і `DATABASE_URL`.

## Структура

```
api/                 NestJS: один код, два процеси
  src/main.ts        api — HTTP для панелі
  src/worker.ts      worker — Telegram-бот і черги BullMQ
  prisma/            схема й міграції
admin/               React + Vite; nginx: статика й проксі /api
docs/                перевірена поведінка Syrve API
docker-compose.yml   postgres, redis, migrate, api, worker, admin
```
